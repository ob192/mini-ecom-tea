# Пропсы и композиция

Общий компонент (в `entities`, `features`, `widgets`, который вызывают из разных мест) остаётся простым и делает
одно. Если одному месту нужно что-то особое, компонент **не расширяют пропсом**: нужное **собирают** из простых
частей там, где эта потребность возникла.

## Чего не допускаем

| Запах                                  | Как выглядит                                                    | Признак в коде                                  |
| -------------------------------------- | --------------------------------------------------------------- | ----------------------------------------------- |
| **Flag argument** (Fowler)             | проп переключает режим: `isCompact`, `inverse`, `layout="grid"` | `cond && "…"` в нескольких элементах            |
| **Control coupling**                   | вызывающий передаёт указание, какую ветку выполнить             | `if (mode === …)`, разные `return` по пропу     |
| **The Wrong Abstraction** (Sandi Metz) | к готовому компоненту добавили параметр и `if` под новый случай | проп нужен ровно одному вызывающему             |
| **Prop explosion**                     | много необязательных пропсов, каждый для своего места           | описание `Props` длиннее разметки               |
| **Проп про чужую задачу**              | имя называет задачу вызывающего: `isPrivacyPage`                | в имени понятие страницы, а не самого компонента |

## Проверка перед новым пропом

1. **Проп меняет, *какая* разметка рисуется?** Значит, это два компонента. Выбор — в месте вызова.
2. **В имени есть понятие одного вызывающего?** Значит, это его забота: обёртка, `children`, `className`.
3. **Сколько веток `cond && "…"` добавляет проп?** Больше одной — проп не на своём месте.
4. **Правило трёх.** Не обобщать, пока одно и то же не понадобилось в трёх местах. До этого лучше два простых
   компонента рядом: дублирование дешевле неправильной абстракции (ссылки-«пилюли» в контактах и в футере —
   два компонента, не один с флагом).

## Чем заменять

| Что нужно вызывающему                 | Вместо пропа-режима                                          |
| ------------------------------------- | ------------------------------------------------------------ |
| другая вёрстка                        | другой компонент, выбор в месте вызова                       |
| другой цвет на другой поверхности     | `className` с цветом на корне, внутри — `currentColor` (`LayoutLogo`) |
| стиль корня                           | `className` + `cn()`                                         |
| своё содержимое внутри                | `children` или слот-проп с `ReactNode` (`icon`, `action`)    |
| реакция на действие                   | колбэк `on{Event}`                                           |

**Допустимо:** `variant` / `size` через CVA у примитивов `shared/components/ui` (**`21-shared-components.md`**) —
закрытый набор стилей одного элемента, а не другая разметка под одного вызывающего.

## Чеклист

1. Проп нужен больше чем одному вызывающему и не переключает разметку.
2. Разная вёрстка — разные компоненты, выбор в месте вызова.
3. Ни одной ветки `cond && "…"`, добавленной ради одного вызывающего.
