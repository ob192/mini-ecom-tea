# Критерии мобильного удобства

Пороги собраны 2026-10-14 по первоисточникам. У каждого правила метка статуса — она решает, как
формулировать находку:

- **[WCAG]** — стандарт W3C WCAG 2.2 (Recommendation, 12.12.2024). Нарушение AA — дефект.
- **[Платформа]** — Apple HIG, Material 3. Для веба не норма, но это то, к чему привыкла рука.
- **[Исследование]** — NN/g, Baymard, Hoober, Parhi. Эвристика с данными за ней.
- **[Техника]** — поведение браузеров: MDN, web.dev, WebKit, Next.js, Tailwind.

Уровень в скобках — уровень находки по умолчанию в отчёте (SKILL.md, шаг 5). Поднимать его можно,
если цель — основное действие экрана или стоит у края; опускать — только с объяснением.

Пересчёт: на телефоне 1 CSS px ≈ 0,16 мм. 24 px ≈ 4 мм, 44 px ≈ 7 мм, 48 px ≈ 7,7 мм,
1 см ≈ 62 px. Таблицы «мм → px» из десктопных источников (96 dpi) занижают пиксели в ~1,6 раза.

_Essential_ он не знает; перекрытие видит только в текущем экране; кликабельный `<div>` находит
только по `cursor: pointer`.

## 1. Размер цели и отступы

| Порог                                                        | Статус            | Источник                             |
| ------------------------------------------------------------ | ----------------- | ------------------------------------ |
| ≥ 24×24 CSS px или исключение по отступу                     | [WCAG] 2.5.8, AA  | WCAG 2.2                             |
| ≥ 44×44 CSS px, исключения по отступу нет                    | [WCAG] 2.5.5, AAA | WCAG 2.2                             |
| 44×44 pt по умолчанию, 28×28 pt минимум                      | [Платформа]       | Apple HIG, Accessibility (2025)      |
| ≥ 48×48 dp, зазор ≥ 8 dp                                     | [Платформа]       | Material 3, Structure → Target sizes |
| ≥ 1×1 см; в центре экрана ~7 мм, у краёв и в углах ~11–12 мм | [Исследование]    | NN/g 2019; Hoober 2017               |

- **`fail-2.5.8` (Блокер).** Цель меньше 24px и круг Ø24px вокруг её центра задевает соседнюю
  цель. Исключения, которые скрипт не видит сам: _Equivalent_ (то же действие есть рядом крупной
  целью), _Essential_, нестилизованный нативный контрол. Ссылки внутри предложения скрипт уже
  пропускает (_Inline_).
- **`small-spaced` (Улучшение).** Меньше 24px, но проходит по отступу. По норме допустимо; на
  телефоне палец всё равно промахивается, и это стоит сказать.
- **`below-44` (Серьёзно для основного или частого действия, иначе Улучшение).** Сюда попадают
  кнопки шапки, основные действия экрана, вкладки, пункты меню и фильтров, иконки-кнопки. Цель для
  телефона — 44px по меньшей стороне, если DESIGN.md проекта не задаёт другую. Визуальная высота
  кнопки (28, 36px) может быть меньше: зону касания расширяют под `pointer-coarse:`, рисунок не
  меняется.
- **Соседи ближе 8px** (`tightNeighbours`) поднимают `below-44` с Улучшения до Серьёзно. До
  Блокера близость не поднимает: Блокер — только нарушение AA, а его скрипт уже отметил как
  `fail-2.5.8`.
- **Мёртвые зоны.** Чекбокс, переключатель и радио вместе с подписью — одна цель (`<Label
htmlFor>` или обёртка). Иконка-кнопка закрытия диалога или шита без паддинга даёт зону ~16px.
- **Как чинить, не раздувая вид.** Зону касания расширяют без изменения рисунка:
  `pointer-coarse:size-11` / `pointer-coarse:h-11`, паддинг с компенсирующим отрицательным
  margin, или псевдоэлемент `relative after:absolute after:-inset-2`. Перекрытая другой целью
  площадь не засчитывается — расширенные зоны соседей не должны налезать друг на друга.
- **Источники размера** — примитивы в `ui`-папке проекта (алиас `ui` в `components.json`, иначе
  `src/shared/components/ui`): `button` (все `size`, включая `icon-*`), `badge`, пункты меню, опции
  комбобоксов, пагинация, вкладки, крестик закрытия в `dialog`/`sheet`, `switch`, шрифт в `input` и
  `textarea`. Правка размера в примитиве под `pointer-coarse:` чинит все места разом и не трогает
  десктоп.

## 2. Досягаемость

[Исследование] Hoober 2017 (UXmatters), NN/g «Bottom Sheets» 2023.

- Самая точная зона — **центр экрана**; туда основной контент и частые действия.
- Края и углы требуют **более крупных** целей (11–12 мм ≈ 70 px высоты зоны касания).
- Опасные действия (удалить, выйти, отписаться) — в стороне от частых.
- Хват меняется каждые несколько секунд; не рассчитывать на одну руку или одну сторону.
- Карту «нижние 50% экрана — зелёная зона» **не использовать**: Hoober сам отозвал её в 2017,
  NN/g её оспаривает. Нижняя панель хороша постоянной видимостью, а не досягаемостью.

Находка: частое действие (основная кнопка экрана, переключение шагов) — маленькая цель в верхнем углу (Серьёзно).

## 3. Жесты и указатель

| Правило                                                                          | Статус           |
| -------------------------------------------------------------------------------- | ---------------- |
| Всё, что делается свайпом, multipoint или жестом по пути, делается и одним тапом | [WCAG] 2.5.1, A  |
| Перетаскивание имеет альтернативу без перетаскивания                             | [WCAG] 2.5.7, AA |
| Действие срабатывает на отпускание и его можно отменить                          | [WCAG] 2.5.2, A  |
| Ориентация не заперта; экран работает в landscape                                | [WCAG] 1.3.4, AA |

- Слайдер, который листается только свайпом (стрелки скрыты на телефоне), — нарушение 2.5.1
  (Блокер), если весь контент слайдера не доступен другим путём. Автопрокрутка не альтернатива.
- Pinch-zoom не блокировать. Всё, что листается свайпом (галерея, шаги), дублируется тап-зонами
  или кнопками.
- Шит закрывается кнопкой, а не только свайпом вниз (NN/g).

## 4. Поля ввода и клавиатура

- **Шрифт в `input`/`textarea`/`select` ≥ 16px** на телефоне, иначе iOS Safari зумит страницу при
  фокусе и часто не отзумливает обратно. [Техника; Apple не документирует, поведение стабильно.]
  (Серьёзно.) Лечится `text-base md:text-sm` — так делает сам shadcn Input. Подавлять зум через
  `maximum-scale=1` нельзя (раздел 5).
- Клавиатура под задачу: `type="email"`, `type="search"`, `inputmode="numeric"` для кодов,
  `autocomplete` (`username`, `current-password`, `new-password`, `one-time-code`) —
  [WCAG] 1.3.5, AA для полей с данными пользователя. `enterkeyhint="search"` в поиске,
  `"send"` в комментарии. (Улучшение.)
- `autoFocus` на телефоне открывает клавиатуру и сдвигает вёрстку — только там, где ввод и есть
  цель экрана (поиск в модалке).
- Фиксированная нижняя панель под полем ввода: в iOS клавиатура перекрывает её
  (`interactive-widget` в iOS не поддерживается). Проверять, видно ли поле и кнопку отправки.
- `spellCheck={false}` на email, кодах и логинах; вставку не блокировать.

## 5. Зум, viewport, ширина экрана

- **Зум не запрещён**: нет `user-scalable=no`, `maximum-scale` < 2 (лучше не задавать вовсе).
  [WCAG] 1.4.4, AA; axe `meta-viewport` — critical. (Блокер.) Chrome на Android этот запрет
  соблюдает. Ловушка: пример в документации Next.js `generateViewport` показывает
  `maximumScale: 1, userScalable: false` — не копировать.
- **Нет горизонтального скролла на 320px** — [WCAG] 1.4.10, AA. (Блокер.) Исключение: контент,
  которому нужна двумерная раскладка, — карты, широкие таблицы в своём скролл-контейнере.
  Частые причины: `w-screen`/`100vw`, фиксированные `min-w-*`, длинные непереносимые названия,
  email и URL (лечится `break-words`, `min-w-0` у flex-детей).
- **`h-screen` / `100vh`** на телефоне выше видимой области при открытых панелях браузера.
  Для экранов «влезть целиком» — `min-h-svh`, для полноэкранных режимов и оверлеев — `h-dvh`.
  [Техника] web.dev, поддержка во всех движках. (Улучшение; Серьёзно, если прячет кнопку.)
- Межстрочный 1,5 / абзац 2 / буквы 0,12 / слова 0,16 не ломают вёрстку — [WCAG] 1.4.12:
  текстовым контейнерам без фиксированной высоты.

## 6. Hover и отклик на нажатие

- **В Tailwind 4 `hover:` работает только при `(hover: hover)`**: на телефоне hover-стили не
  применяются вообще. Значит, всё, что появляется через `hover:`, `group-hover:`, `peer-hover:`
  (`opacity-0 group-hover:opacity-100`, `hidden group-hover:flex`), на телефоне **невидимо и
  недоступно**. (Блокер, если это действие; Улучшение, если украшение.) Лечится видимостью по
  умолчанию под `pointer-coarse:` или отдельным тапом.
- Важное не прятать в тултип: на тач-экране он может не открыться. Контент по hover/focus
  закрывается, на него можно навести, он не исчезает сам — [WCAG] 1.4.13.
- **Цель без имени** (`unnamed`) — иконка-кнопка без `aria-label`: экранный диктор читает
  «кнопка», голосовое управление не может её назвать. [WCAG] 4.1.2, A. (Блокер.)
- **`<div onClick>`** (`nonSemantic`) — не фокусируется с клавиатуры, не объявляется как кнопка.
  [WCAG] 2.1.1 и 4.1.2, A. (Серьёзно; чинится `<button type="button">`.)
- **Отклик на нажатие.** Preflight Tailwind 4 ставит `-webkit-tap-highlight-color: transparent`,
  системной вспышки нет. У каждой кастомной кнопки нужен `active:`-стиль или смена
  `data-[state]` — [Платформа] Apple HIG требует press state. (Улучшение.)
- Быстрые повторные тапы (тап-зоны, +/−, счётчики): `touch-action: manipulation`, иначе
  второй тап станет double-tap-zoom. `touch-action: none` на прокручиваемом контенте ломает зум.

## 7. Закреплённые элементы и safe area

- **Закреплённый блок выше экрана** (`tallerThanScreen`) без своей прокрутки — нижняя часть
  содержимого недостижима: скроллится страница под ним, а не он. (Блокер.) Чинится
  `max-h-[calc(100dvh-2rem)]` на контейнере и `overflow-y-auto` на теле.
- **Перекрытая цель** (`covered`) — постоянная панель, кнопка-плавашка или баннер лежит поверх
  цели. (Серьёзно.) Временные оверлеи, открытые самим аудитом, — не находка.
- Сумма высот `fixed`/`sticky` панелей (`pinned[].screenShare`) больше 25% экрана — Серьёзно; в
  landscape (высота ~375px) проверять отдельно.
- Фокус не уходит целиком под шапку или нижнюю панель — [WCAG] 2.4.11, AA. Лечится
  `scroll-padding-top`/`-bottom` под высоту панелей.
- `env(safe-area-inset-*)` работает только вместе с `viewport-fit=cover` (Next: `viewport.viewportFit`,
  в App Router; в Pages Router — `<meta name="viewport">`). Без `cover` Safari сам отодвигает контент
  от выреза — это не ошибка, и `env()` там равен 0; но фиксированная нижняя панель и нижние шиты должны иметь
  `pb-[max(1rem,env(safe-area-inset-bottom))]` или аналог, если `cover` включат.
- Модалки и шиты: явная кнопка закрытия ≥ 44px, `overscroll-behavior: contain`.

## 8. Читаемость

- Основной текст ≥ 16px [Исследование/практика], у Apple 17 pt по умолчанию, минимум 11 pt
  [Платформа]. Текст меньше 12px (`smallText` в замере) — Улучшение; если это основной текст или
  подпись к действию — Серьёзно. Lighthouse с версии 13 размер шрифта не проверяет.
- Боковые поля ≥ 16px, межстрочный ≥ 1,5 для описаний, отзывов и длинного текста.

## 9. Ручная проверка

Скрипт не видит — смотреть на скриншоте и в коде:

- основное действие экрана на виду в первом экране и достаточно крупное;
- жесты без альтернативы (раздел 3), hover-only действия (раздел 6);
- соседние цели, у которых визуально нет границ (ссылки-иконки в ряд, звёзды рейтинга, пагинация);
- опасные действия рядом с частыми;
- поле ввода, перекрытое клавиатурой или нижней панелью;
- состояние нажатия у кастомных кнопок.

Эмулятор **не воспроизводит**: автозум iOS на полях ввода, ненулевые safe area, тонирование панелей
Safari 26, реальную экранную клавиатуру. Такие пункты выносятся в «Не проверено» с пометкой
«проверить на iPhone».

## 10. Поиск по коду

Из корня приложения; `UI` — папка примитивов проекта. Каждый результат — кандидат, а не находка: сверять с замером.

```bash
# Мелкие размеры примитивов — сколько мест затронет правка примитива (оба вида пропа: "sm" и {"sm"})
grep -rnoE 'size=\{?"(xs|sm|icon-xs|icon-sm|icon-md|icon|dense)"\}?' src | sed -E 's/.*size=\{?"([^"]+)".*/\1/' | sort | uniq -c

# Найти место по классам из замера: JSX многострочный, поэтому искать один характерный класс,
# а не тег вместе с классом — например, grep -rn 'h-\[18px\]!' src

# <div onClick> и другие кликабельные не-кнопки (тег на строке перед onClick)
grep -rn -B1 'onClick=' src --include='*.tsx' | grep -E '<(div|span|li|img|p)\b'

# Шрифт меньше 16px в полях ввода (примитивы и переопределения)
grep -nE 'text-(xs|sm|\[1[0-5]px\])' $(ls $UI/*.tsx | grep -iE '/(input|textarea)\.tsx$')
grep -rnE '<(Input|Textarea|textarea|input|SelectTrigger|CommandInput)\b[^>]*text-(xs|sm|\[1[0-5]px\])' src --include='*.tsx'

# Действия, видимые только по hover (на телефоне не появятся)
grep -rnE '(group|peer)?-?hover:(opacity-100|visible|block|flex|inline|pointer-events-auto)' src --include='*.tsx'

# 100vh на телефоне
grep -rnE '\b(min-h|h|max-h)-screen\b|100vh' src

# Viewport, safe area, touch-action
grep -rn -A6 'export const viewport\|name="viewport"' src/app/layout.tsx src/pages/_document.* src/pages/_app.* src/components 2>/dev/null
grep -rnE 'safe-area|viewportFit|touch-action|touch-manipulation' src

# Слайдеры и карусели: стрелки, скрытые на телефоне (остаётся только свайп)
grep -rnEi 'prev|next|arrow' src --include='*.tsx' | grep -E 'max-sm:hidden|max-md:hidden|hidden sm:'
```
